# Rubric: is this pull request ready to submit?

Every check reads the candidate PR's diff, evidence, and text against the plan it claims to implement, the issue, and the repo's stated standards. Grade the artifact itself; the description's account of the diff is a claim to verify, never evidence that the diff matches. references/evidence-guide.md says where each check's evidence lives; procedure.md says when and how to gather it.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | Every hunk in the diff, file by file, read against the plan's in-scope changes, deferrals, and deviation notes (Plan fidelity family) | Every changed file and hunk is a planned change, the test for it, or something recorded in the plan's deviation note; and every change the plan commits to appears in the diff, unless the plan records it as deferred or as a deviation. Fails on any hunk touching a file or behavior the plan never names (a rewrite of another function, a renaming pass, a new option, flag, or setting, reworded unrelated text), or on a planned change missing from the diff with no deviation note. Deferring part of the fix passes when the plan records it. | required |
| description-truthful | The PR title and description read against the diff inventory and the plan (Plan fidelity family) | The description's claims about scope and delivery hold against the diff: claims of fidelity to the plan ("implements the plan exactly", "no changes beyond the plan"), claims of absence ("no functional changes outside X"), and claims that a planned deliverable is done (docs, a config change, a second fix) are each checked against what the diff contains. A deferral or shortfall recorded in the plan is restated in the description. Fails when such a claim is contradicted by the diff, or when the description credits a deliverable no hunk contains. Wording about test coverage is graded by fix-evidenced, not here. | required |
| fix-evidenced | The test evidence read against the issue's reported failure, the plan's test plan, and which code path the diff changes (Test evidence family) | The evidence shows, as commands or inputs with their observed output, the issue's reported failure before the change and the corrected behavior after it, on the path the issue reports and the diff changes. When the plan names a second failure mode of the bug itself, it is either shown before and after or covered by a test the diff adds. Control runs and suite results may be stated without output. Fails on "tests pass", "works on my machine", "verified locally" with no before and after shown; on before and after that exercise only a control or a path the diff does not change; or on a reported failure mode with neither a shown re-run nor an added test. | required |
| diff-clean | Every added and removed line in the diff, and each hunk as a whole (Diff quality family) | Every changed line serves the fix, its test, or a recorded deviation. Identical removed-and-added lines count as part of the change when the same hunk restructures the code around them (lines moved by a reorder, wrapped in a new block, or kept beside changed logic). Fails on debug output left in (active or commented out), commented-out code or earlier attempts, dead functions or allow-unused markers added, TODOs added to untouched code, an import restructure no new import needs, a hunk whose only effect is re-printing, re-indenting, or reformatting lines with unchanged content, or any unrelated hunk folded in. | required |
| template-met | The description read against the repo-facts PR template, checklist, and contributing asks; the diff read against any file the template or contributing requires (Standards and comms family) | Every section and checklist item the repo's PR template or contributing guide requires is present with real content, including the issue link where asked, and any file the repo requires with a change (a changelog or whatsnew entry) is in the diff. Passes when the repo states no template. Fails when a required section, checklist, issue link, or required file entry is missing or left as placeholder text. | required |
| ai-policy-met | The repo-facts contribution policy read against the PR description (Standards and comms family) | Treat every package as AI-assisted work. If the repo's stated policy requires disclosing AI use in pull requests, or all AI usage in any form, the description discloses the tool and the extent of the help. Passes when the repo states no AI policy or one that is satisfied without a disclosure line. Fails when a required disclosure is absent. | required |
| repo-checks-shown | The test evidence (Test evidence family) | The evidence shows the repo's test suite, or the tests for the touched module, run on the branch with the result. | preferred |
| regression-test-added | The diff (Test evidence family) | The diff adds or tightens a test that fails before the fix and passes after it. | preferred |

## Verdict rule

accept when every required check grades pass. reject when any required check grades fail or unclear: unclear counts as fail, because a PR that cannot be verified from the package is not ready to submit. Preferred checks are reported and never change the verdict.
